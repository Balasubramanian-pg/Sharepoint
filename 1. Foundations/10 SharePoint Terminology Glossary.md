# SharePoint Terminology Glossary

Canonical documentation for SharePoint Terminology Glossary. This document defines concepts, terminology, and standard usage.

## Purpose

The SharePoint Terminology Glossary is a comprehensive resource that aims to provide a unified understanding of the terminology used within the SharePoint ecosystem. This glossary addresses the problem of inconsistent terminology usage, which can lead to confusion, miscommunication, and errors among SharePoint users, administrators, and developers. By establishing a standardized vocabulary, this glossary facilitates effective communication, collaboration, and knowledge sharing within the SharePoint community.

> [!NOTE]
> This documentation is intended to be implementation-agnostic and authoritative.

## Scope

**In scope:**
* SharePoint-specific terms and definitions
* Core concepts and fundamental ideas related to SharePoint
* Standard models and best practices for SharePoint terminology usage

**Out of scope:**
* Tool-specific implementations, such as third-party add-ons or custom solutions
* Vendor-specific behavior, including proprietary features or extensions
* Non-SharePoint related terminology or concepts

## Definitions

| Term | Definition |
|------|------------|
| SharePoint | A web-based collaborative platform developed by Microsoft, used for document management, content management, and workflow automation. |
| Site Collection | A top-level container in SharePoint that holds a group of related sites, lists, and libraries. |
| Web Application | A SharePoint web application is a container that hosts one or more site collections, providing a set of features and services. |
| List | A SharePoint list is a collection of items, such as documents, tasks, or contacts, that can be managed and collaborated on. |
| Library | A SharePoint library is a specialized list that stores files, such as documents, images, or videos, and provides features like versioning and check-out. |
| Workflow | A series of automated or manual tasks that are executed in a specific order to achieve a business process or goal. |
| Content Type | A content type is a reusable template that defines the structure and metadata of a piece of content, such as a document or list item. |

> [!TIP]
> Definitions should be stable over time; avoid contextual language.

## Core Concepts

### SharePoint Architecture
SharePoint architecture refers to the overall structure and organization of a SharePoint environment, including the relationships between web applications, site collections, sites, lists, and libraries.

### Collaboration and Content Management
Collaboration and content management are core concepts in SharePoint, enabling users to work together on content, manage documents and files, and automate business processes.

### Security and Permissions
Security and permissions are critical concepts in SharePoint, controlling access to content, features, and functionality, and ensuring that users can only perform actions they are authorized to do.

## Standard Model

The standard model for SharePoint terminology usage is based on the official Microsoft documentation and industry best practices. It is recommended to use the terms and definitions provided in this glossary to ensure consistency and clarity in communication.

> [!IMPORTANT]
> Deviations from the standard model should be explicitly documented and justified.

## Common Patterns

* Using site collections to organize related sites and content
* Creating custom content types to standardize metadata and structure
* Implementing workflows to automate business processes and tasks
* Utilizing libraries to manage and collaborate on files and documents

## Anti-Patterns

> [!WARNING]
> These anti-patterns often lead to maintenance or scalability issues.

* Using lists to store files and documents, instead of libraries
* Creating multiple site collections with similar content and structure
* Not using content types to standardize metadata and structure
* Implementing custom solutions that are not scalable or maintainable

## Edge Cases

> [!CAUTION]
> Edge cases are frequently overlooked and may cause incorrect assumptions.

* Handling large volumes of content or user traffic in a SharePoint environment
* Integrating SharePoint with other systems or platforms
* Managing security and permissions in a complex or dynamic environment
* Troubleshooting issues with custom solutions or third-party add-ons
