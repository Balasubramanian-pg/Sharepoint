# Viewing Available Site Designs

Canonical documentation for Viewing Available Site Designs. This document defines concepts, terminology, and standard usage.

## Purpose

The purpose of Viewing Available Site Designs is to provide users with a comprehensive overview of the various site design options available to them. This topic exists to address the problem space of site design selection, where users need to choose a suitable design for their website or application. The ability to view available site designs enables users to make informed decisions about the layout, structure, and overall aesthetic of their site, ultimately enhancing the user experience and improving the site's effectiveness. This documentation aims to provide a clear understanding of the concepts, terminology, and standard usage related to viewing available site designs, ensuring that users can navigate and utilize the available designs efficiently.

> [!NOTE]
> This documentation is intended to be implementation-agnostic and authoritative.

The scope of Viewing Available Site Designs includes the concepts, terminology, and standard usage related to the discovery and exploration of available site design options.

## Core Concepts

The core concepts of Viewing Available Site Designs include:

### Site Design Templates
Site design templates are pre-built designs that can be used as a starting point for creating a website or application. These templates typically include a predefined layout, visual elements, and content organization.

### Design Customization
Design customization refers to the process of modifying a site design template to suit the user's needs. This can include changing the layout, adding or removing visual elements, and applying different themes.

### Site Design Preview
Site design preview allows users to visualize how a site design will look and function before applying it to their website or application. This feature enables users to explore different design options and make informed decisions about the best design for their needs.

## Standard Model

The standard model for Viewing Available Site Designs involves the following steps:

1. **Site Design Template Selection**: The user selects a site design template from a library of available designs.
2. **Design Customization**: The user customizes the selected template to suit their needs.
3. **Site Design Preview**: The user previews the customized design to ensure it meets their requirements.
4. **Design Application**: The user applies the customized design to their website or application.

> [!IMPORTANT]
> Deviations from the standard model should be explicitly documented and justified.

## Common Patterns

Common patterns associated with Viewing Available Site Designs include:

* **Template-based design**: Using pre-built site design templates as a starting point for creating a website or application.
* **Customization**: Modifying a site design template to suit the user's needs.
* **Preview and iteration**: Iteratively previewing and refining a site design until it meets the user's requirements.

## Anti-Patterns

Anti-patterns to avoid when Viewing Available Site Designs include:

* **Over-customization**: Making excessive changes to a site design template, resulting in a design that is no longer maintainable or scalable.
* **Lack of preview**: Failing to preview a site design before applying it to a website or application, resulting in unexpected layout or functionality issues.

> [!WARNING]
> These anti-patterns often lead to maintenance or scalability issues.

Edge cases related to Viewing Available Site Designs include:
