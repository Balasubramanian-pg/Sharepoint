# When to Create a New Site

Canonical documentation for When to Create a New Site. This document defines concepts, terminology, and standard usage.

## Purpose

Describe why this topic exists and what problem space it addresses. This section should be descriptive, not instructional.

The purpose of this documentation is to provide guidance on determining when to create a new site, addressing the complexities of site management, scalability, and maintainability. It aims to help organizations and individuals make informed decisions about site creation, considering factors such as content organization, user experience, and technical infrastructure. By understanding the principles and best practices outlined in this document, stakeholders can optimize their site architecture, reduce costs, and improve overall efficiency.

> [!NOTE]
> This documentation is intended to be implementation-agnostic and authoritative.

## Definitions

## Core Concepts

Explain the fundamental ideas that make up the topic.

### Site Purpose and Scope
A site's purpose and scope define its content, structure, and target audience. Understanding these factors is crucial in determining whether to create a new site or modify an existing one.

### Content Organization
Effective content organization is essential for a site's usability, search engine optimization (SEO), and maintainability. This includes categorization, tagging, and linking of content to facilitate discovery and navigation.

### Technical Infrastructure
A site's technical infrastructure, including hosting, storage, and bandwidth, must be sufficient to support its content, traffic, and user base. Scalability, reliability, and security are critical considerations in this context.

## Standard Model

Describe the generally accepted or recommended model for this topic.

The standard model for site creation involves the following steps:

1. **Define site purpose and scope**: Determine the site's goals, target audience, and content requirements.
2. **Conduct content inventory and analysis**: Assess existing content, identify gaps, and develop a content strategy.
3. **Design site architecture and navigation**: Create a site map, wireframes, and prototypes to visualize the site's structure and user experience.
4. **Develop a technical infrastructure plan**: Choose a hosting platform, select necessary tools and services, and ensure scalability and security.
5. **Implement and test the site**: Build, test, and launch the site, ensuring it meets the defined requirements and user needs.

> [!IMPORTANT]
> Deviations from the standard model should be explicitly documented and justified.

## Common Patterns

Document recurring patterns or approaches associated with this topic.

* **Hub-and-spoke model**: A central site (hub) with multiple subsites or microsites (spokes) that serve specific purposes or audiences.
* **Multi-site architecture**: A single platform or infrastructure supporting multiple, independent sites with distinct content, branding, and user experiences.

## Anti-Patterns

Describe common mistakes or discouraged practices.

> [!WARNING]
> These anti-patterns often lead to maintenance or scalability issues.

* **Site sprawl**: Creating multiple, redundant, or overlapping sites without a clear purpose or strategy, leading to content duplication, confusion, and maintenance challenges.
* **Insufficient planning**: Failing to define site purpose, scope, and technical requirements, resulting in a site that is poorly designed, difficult to maintain, or unable to meet user needs.

## Edge Cases

Explain unusual, ambiguous, or boundary scenarios related to the topic.
