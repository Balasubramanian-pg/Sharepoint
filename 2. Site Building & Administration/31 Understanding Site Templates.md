# Understanding Site Templates

Canonical documentation for Understanding Site Templates. This document defines concepts, terminology, and standard usage.

## Purpose

The purpose of Understanding Site Templates is to provide a comprehensive framework for creating, managing, and utilizing site templates in various contexts, including web development, content management, and digital experience platforms. This topic exists to address the problem space of efficiently creating and maintaining multiple websites or digital experiences that share common characteristics, such as design, layout, and functionality. By leveraging site templates, developers, designers, and content creators can streamline their workflow, reduce duplication of effort, and improve consistency across different sites or experiences.

> [!NOTE]
> This documentation is intended to be implementation-agnostic and authoritative.

## Scope

The scope of Understanding Site Templates includes the concepts, principles, and best practices related to the creation, management, and use of site templates.

**In scope:**
* Template design and development
* Template management and versioning
* Template deployment and integration
* Template customization and extension

**Out of scope:**
* Tool-specific implementations, such as proprietary template engines or CMS-specific template languages
* Vendor-specific behavior, such as custom template features or proprietary template formats
* Low-level technical details, such as template rendering engines or caching mechanisms

## Definitions

The following terms are used throughout this documentation:

| Term | Definition |
|------|------------|
| Site Template | A pre-designed and pre-configured template for creating a website or digital experience, including layout, design, and functionality. |
| Template Engine | A software component responsible for rendering templates into final output, such as HTML or other markup languages. |

## Core Concepts

The core concepts of Understanding Site Templates include:

### Template Structure
A site template typically consists of a combination of static and dynamic components, such as HTML, CSS, JavaScript, and template variables. The template structure defines the organization and hierarchy of these components, including the relationships between different template elements.

### Template Customization
Template customization refers to the process of modifying a site template to meet specific requirements or branding guidelines. This can include changing colors, fonts, layouts, and other visual elements, as well as adding or removing functionality.

### Template Inheritance
Template inheritance is a mechanism that allows site templates to inherit properties, styles, and functionality from parent templates or base templates. This enables the creation of a hierarchy of templates, where child templates can build upon and extend the capabilities of parent templates.

## Standard Model

The standard model for Understanding Site Templates involves the following components and processes:

1. Template design and development: Create a site template with a consistent structure and organization.
2. Template management: Manage and version site templates, including deployment and integration.
3. Template customization: Customize site templates to meet specific requirements or branding guidelines.
4. Template inheritance: Use template inheritance to create a hierarchy of templates and promote code reuse.

> [!IMPORTANT]
> Deviations from the standard model should be explicitly documented and justified.

## Common Patterns

Common patterns associated with Understanding Site Templates include:

* Using a modular template architecture to promote code reuse and flexibility
* Implementing a template inheritance hierarchy to simplify template management and customization
* Utilizing a template engine or template language to streamline template rendering and deployment
* Creating a template library or repository to store and manage site templates

## Anti-Patterns

Anti-patterns to avoid when working with site templates include:

* Using a single, monolithic template for all sites or experiences, which can lead to maintenance and scalability issues
* Failing to version and manage site templates, resulting in template drift and inconsistencies
* Over-customizing site templates, which can lead to template bloat and reduced maintainability
* Ignoring template security and accessibility guidelines, which can compromise the security and usability of sites or experiences

> [!WARNING]
> These anti-patterns often lead to maintenance or scalability issues.

## Edge Cases

Edge cases related to Understanding Site Templates include:

* Handling template conflicts or inconsistencies when using template inheritance or modular template architectures
* Managing template dependencies and versioning when using third-party libraries or components
* Ensuring template accessibility and usability for sites or experiences with unique or complex requirements
* Supporting multiple template languages or engines in a single site or experience

> [!CAUTION]
> Edge cases are frequently overlooked and may cause incorrect assumptions.
